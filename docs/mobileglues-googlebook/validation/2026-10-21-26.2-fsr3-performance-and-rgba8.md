# 26.2 FSR3 performance, RGBA8 images and bridge coverage

Date: 2026-10-21. Device: HP Googlebook 14 `C1L63708PZ`, Snapdragon X1E80100,
Adreno X1-85, ANGLE 2.1 / Vulkan 1.4.295, GLES 3.2.

## Result

The reported 26.2 half-rate was **not a MobileGlues renderer regression**. The
26.2 NeoForge profile had no FSR3 bridge JAR, so it rendered the scene at full
resolution while 1.21.1 used the bridge's 1694x932 Balanced scene. Installing the
0.2.4 26.2 bridge raised the same Sildurs scene from 36 FPS to 66-70 FPS.

## Why the bridge was missing

The root log for 1.21.1 lists
`mgfsr3bridge-0.2.4-1.21.1-neoforge.jar`; the 26.2 `mods` listing contained only
Iris and Sodium. The bridge log showed `Fsr3Bridge loaded=true` and
`scene depth 1694x932` for the bridged lanes. Installing
`mgfsr3bridge-0.2.4-26.2-neoforge.jar` immediately restored the scene scaling and
the framerate.

No MobileGlues guard or draw-path optimization is justified by these measurements.
The frame distribution is stable and the 1.21.1 path remains the baseline.

## RGBA8 image compatibility

`b3b7abf` had excluded ordinary RGBA8 from the immutable `glTexImage2D(null)`
conversion. That decision was based on the empty-atlas symptom later shown to be
the missing `glDrawArraysInstanced` export (`1bd40dc`), not storage immutability.

With the export fix present, removing the RGBA8 carve-out still renders 26.2
correctly (70 FPS) and restores ANGLE's image-load/store contract. Commit
`d6c9d5f` reverts the carve-out. A new wrapper probe allocates RGBA8 with
`glTexImage2D(level 0, null)` and binds it as an image:

```
"image2d_rgba8_null_bind": {"pass": true, "detail": "tex=0 bind=0"}
```

Probe core marker: `src-c33bb3b6d776a863`. The probe is committed as
`01feb52`.

A full Iris pack using RGBA8 custom images was then loaded: iterationRP
`iterationRP-noTAA-test.zip` on 1.21.1 NeoForge. The pack initialized and its
`playerAtlas_img` RGBA8 image path produced no `MG-IMG-ERROR` or image-bind
failure. The bridge loaded with final-pass support and sampled a 1694x932 scene.
The frame still shows iterationRP's known red/orange S1 color state; that is a
separate pack-color defect, not an RGBA8 storage failure. Capture
`/tmp/iteration-1.21.1b.png`, SHA-256 `9ce7460d...`.

The package was restored to Sildurs Vibrant 2.02 Extreme after the run.

## FSR3 bridge coverage

The bridge repository now has ten pinned profiles:

- 1.18.2 Fabric/Forge
- 1.20.1 Fabric/Forge
- 1.21.1 Fabric/NeoForge
- 26.1 Fabric/NeoForge
- 26.2 Fabric/NeoForge

26.1 and future 26.x select the GPU-texture adapter from
`depth_resource=gpu_texture`, not an exact `"26.2"` string. The main-target
accessor supports `GameRenderer.mainRenderTarget()` (26.2) and
`Minecraft.getMainRenderTarget()` (26.1/future), and depth allocation resolves
the actual `GpuFormat`/`TextureFormat` method dynamically. CI now derives its
matrix from `compatibility-lock.json`.

Commits: `b95f259` (capability source), `8576b37` (26.1 lock, tests, CI).

All ten profiles build; the full host/contract/diagnostic suite passes. 26.1 has
**no device qualification** yet.
