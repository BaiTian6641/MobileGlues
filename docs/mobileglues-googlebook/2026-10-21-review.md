# Desktop GL and universal FSR3 bridge review

Date: 2026-10-21. This independent review covers the desktop GL changes after
`d1b97d3`, the context teardown correction in `0220a19`, the APK/probe/quality
tooling, and the standalone bridge at `[workspace]/MobileGlues-FSR3-Bridge`
(initial extraction commit `84c1e5a`). It supplements the execution report and does not
replace the delivery lane or acceptance gates in `AGENTS.md` and
`desktop-gl-gap-closure.md`.

The result is a set of reviewed, reproducible build and host checks. It is not
a claim of complete desktop OpenGL compatibility, eight live Minecraft loader
qualifications, or target-device FSR image-quality/performance acceptance.

## Review scope and method

- Read source and handoff requirements before reviewing implementation. Separate
  baseline defects from regressions introduced by this development slice.
- Examine shader-source ordering, image declaration masking, format/storage/bind
  compatibility, native/JNI ownership and error handling, bridge extraction and
  dynamic linking, generated injection selectors, dependency locking, package
  contents, and CI permissions.
- Compile the shader-source and image translation units with Clang
  `-Wall -Wextra -Werror`; parse real Clang JSON ASTs for `mg_` declarations.
  The compiler parses the complete translation units; the emitted AST inventory
  is intentionally smaller and is not an exhaustive security scan.
- Parse nine actual Android translation units using their CMake compile
  commands, including `__ANDROID__` JNI code. Run clang-tidy analyzer, bugprone,
  CERT, performance and misleading-indentation rules with an explicit existing
  diagnostic baseline. Do not turn a warning increase into a new baseline merely
  to pass CI.
- Parse common and generated bridge Java with the JDK compiler AST, compile
  with Java 17 bytecode and `-Xlint:all -Werror`, and inspect the actual pinned
  Iris/Oculus classfiles and call instructions without executing downloaded code.
- Review comments and exception boundaries manually. AST counts do not establish
  that comments are accurate, resources are correctly owned, or game behavior
  is equivalent to desktop OpenGL.

## Findings closed during development

| Finding | Origin | Correction and evidence |
|---|---|---|
| Late uniform relocation crossed custom type, macro-array and precision dependencies. | Existing hoist mechanism, exposed during G0 review. | Restrict relocation to simple built-in declarations with literal array lengths and no initializer; preserve directive/precision barriers. Real GLSL compiler repros and host regressions cover the dependency cases. |
| A function starting after a block-comment terminator, including a return type split onto the previous line, could anchor insertion inside the comment. | G0 edge case. | Preserve the original source when a candidate statement starts inside a block comment. Dedicated comment/split-return host cases cover the failure. |
| Unused macro bodies could be interpreted as image declarations and inject an unconditional failure. | Image declaration scanning regression found during review. | Skip complete preprocessor logical lines, including LF and CRLF continuation lines. Original/transformed GLSL repro and three targeted host regressions cover it. |
| Proposed new narrow-format widening was stronger than the numerical evidence. | Proposed G1 expansion. | New normalized/half/narrow-signed cases remain explicit unsupported mappings when exact semantics cannot be established. Existing widening compatibility paths are identified as deviations; compiling a widened image is not proof of quantization, clamping or overflow equivalence. |
| JNI state persisted after context destruction; the direct FSR path could discard a raw session pointer. | Existing lifecycle defect. | Remove the JNI map entry at context release and abandon/delete both native session owners without issuing GL calls into a replacement context. The ownership fixture links the real session API and verifies two constructions, two abandonments, two deletions and no unsafe destruction. |
| JNI resize teardown retained its motion program. | Existing lifecycle defect. | Delete the program on valid-current-context teardown and reset its uniform locations/compile-failure state. |
| The shader-stage probe used a three-element status array for a four-stage tessellation pipeline. | Existing probe defect, independently found by the image/probe agent. | Allocate status storage from the actual shader count. This correction makes the harness suitable for four-stage tests; it is not itself a tessellation acceptance result. |
| The bridge could map a second MobileGlues core and publish an incomplete native function table. | Existing bridge implementation. | Use `RTLD_NOLOAD` only; resolve every mandatory symbol before publishing the candidate handle. Host JNI tests use the real dynamic linker to reject an unmapped core and repeated incomplete-ABI attempts, then accept and dispatch to an already loaded complete fixture. |
| Scene colors could be resized while retaining an incompatible native-size depth texture after allocation failure. | Existing bridge implementation. | Compute the entire new allocation before changing injected arguments, reject unknown formats/incomplete FBOs, delete rejected resources and propagate coherent-allocation failure. Preserve the 26.2 GpuTexture ownership API, source format and usage. |
| Reflection/GL failures could leave bindings or clear state changed. | Existing bridge implementation. | Restore texture/FBO bindings, scissor, depth mask and depth-clear state through `finally` paths. Host failure injection verifies restoration and explicit failed-clear reporting. |
| The bridge swallowed `Throwable` and appended repetitive failure logs to a game-directory file. | Existing bridge implementation. | Catch recoverable exceptions/linkage errors, retain fatal VM errors, use launcher stderr, and rate-limit repeated submission failures. The Java AST inventory finds no `catch (Throwable)` in common source. |
| Method existence/constant-pool inspection alone did not prove an allocation hook existed in its caller. | Initial standalone build verification. | Decode JVM instruction boundaries and verify the exact RenderTargets constructor/resize invocation in its calling pipeline method; verify trace selectors too. Descriptor mutation is a negative build test. |
| Android release/API trace fields used the wrong reflection owner; the marker-file comment described the wrong location. | Existing diagnostic source. | Read `RELEASE`/`SDK_INT` from `android.os.Build$VERSION` and describe the actual game-directory marker. |
| Three inefficient string construction diagnostics were introduced in image metadata. | New implementation. | Use insert/append; the affected translation unit returns to zero scoped diagnostics. |
| Strict image representation validation rejected texture-zero unbinds using desktop R8, including the standard multi-bind reset. | Regression identified in final review of `788ef3c`. | Validate all 39 desktop image-format arguments separately, use an unused legal GLES format only for texture zero, and preserve rejection of unsupported nonzero image storage. Host checks cover all 39 formats, invalid enums and the continued narrow-storage failure. |
| Desktop image uniform writes were forwarded to GLES, which rejects them. | Existing API-semantics defect exposed by strict probe error collection. | Handle image `1i`/`1iv` updates in the existing logical binding map and retain ordinary-uniform driver calls. Validate the full applied array before changing state, reject invalid unit/count inputs, and ignore excess array elements. |
| Array-write bounds were too small when a provider reports each array element separately. | New uniform-validation edge found in independent review. | Normalize the remaining active-array extent after reflection. A host case with two separate element records verifies that a two-element write remains valid. |
| Ordinary uniform failures stayed in the backend error state instead of reaching the application's wrapper error queue. | Existing wrapper defect isolated by the new invalid-location probe. | After each of the four ordinary uniform setter calls, transfer its backend error into the wrapper queue. Handled image writes keep their own desktop validation. The error probe now checks all four invalid-location forwarding branches. |

The unbind and format-error contracts were checked against section 8.26 and
table 8.26 of the [OpenGL 4.6 specification](https://registry.khronos.org/OpenGL/specs/gl/glspec46.core.pdf).
An invalid format argument produces `GL_INVALID_VALUE`; texture-zero unbinding
must not require a backing texture representation.

## Reproducible evidence

The reusable core entry point is `tools/quality/audit.py`; its README describes
the exact scope and existing diagnostic budget. The final independent core
review run was:

```sh
python3 tools/quality/audit.py \
  --compiler "$HOME/Android/Sdk/ndk/28.2.13676358/toolchains/llvm/prebuilt/linux-x86_64/bin/clang++" \
  --target x86_64-linux-gnu \
  --compile-db build/android-arm64-release/compile_commands.json \
  --output [temporary]/mobileglues-review/review-final
```

It passed the three strict host compiler/AST checks, the session ownership
fixture, and all seven actual Android parser/analyzer checks. The generated
summary records individual source SHA-256 values; command and diagnostic logs
remain beside it. Temporary local evidence can be regenerated and is not a
permanent hosted artifact.

After the final null-unbind correction, the same audit passed again with output
under `[temporary]/mobileglues-review/review-unbind/`. Its focused image metadata test
also passed with `-Wall -Wextra -Werror`. The subsequent uniform correction adds
strict helper tests and both `drawing.cpp` and `image_bindings.cpp` to the ongoing
Android audit. Their additional diagnostics were reviewed against unchanged code.
The expanded final run at `[temporary]/mobileglues-review/review-nine-final/summary.json`
passed all nine Android translation units with 26 existing diagnostics and zero
new diagnostics. The recorded translation-unit hashes matched the final source
when checked after completion; the strict image-uniform fixture passed as well.

In the standalone bridge checkout, `python3 tools/test.py --profile all` passed
all eight host contract sets, negative descriptor checks, package isolation,
Java 17 class-version checks, native resource checksums, and real JNI loaded-core
binding tests. The common Java AST review found zero broad `Throwable` catches
and no syntax errors. The final cleanup adds next-frame scope recovery and removes
the remaining empty optional-diagnostic catches; CI reruns the parser on common
and generated adapter code rather than relying on a fixed method-count claim.

These host fixtures deliberately do not emulate successful Minecraft rendering.
They verify contracts such as failed GL operations restoring prior state and
incomplete native bindings remaining unavailable.

## Security and distribution review

The bridge helper is extracted into a fresh private directory with owner-only
permissions, uses bounded reads and a bundled SHA-256 manifest, and is unlinked
after loading. The helper selects ARM64 or x86_64 explicitly. Dependency downloads
use HTTPS, a size bound and pinned content hashes. Release artifacts include the
bridge and helper, not Minecraft/Iris/LWJGL classes or host fixture classes.
Optional trace buffering is bounded to 12 Mi UTF-16 code units, 3,000 events and
120 frames; that character bound is not a claim of a 12 MiB UTF-8 output file.

The Android workflow builds both native ABIs with pinned NDK r28c, stages a clean
checkout of upstream plugin commit `f5105e4ddd1752cccdcc6421c402960d40ec3d9d`, and
copies hash-recorded core libraries into that disposable checkout. The preparation
script refuses a dirty or unexpected plugin revision. It preserves
`useLegacyPackaging = true`, required by the launcher's native-library-directory
loading path. The maintained dirty sibling plugin checkout is not used.

The packaging adaptation pins the Gradle distribution digest and R8 8.13.19 for
the upstream Kotlin metadata. Three upstream test assertions are updated to the
existing decoder/native `DisableIfPossible` fallback; tests are not skipped.
Both debug and unsigned-release APKs passed independent validation of ARM64 and
x86_64 ELF machine types and every packaged native library's 16 KB LOAD alignment.
The packaging run reported 51 unit tests, zero lint errors and 47 existing Android
lint warnings. APKs are build artifacts, not signed production releases or proof
of installation/runtime behavior.

Both new build workflows use pinned action commits, read-only repository
permissions, disabled checkout credential persistence, bounded job durations,
and per-commit/profile artifact names. The bridge workflow builds all eight
profiles, runs contract/AST checks and compares a second build's JAR bytes. The
older iOS workflow is manual-only and pins its downloaded toolchain/hash.
There is no release-signing secret or automatic release publication in these jobs.

The wrapper runner requires an explicit ADB serial and records device identity,
core/probe hashes, process status and per-check results. Its writes are confined
to a hash-named `[device temporary storage]` directory and the requested local output path.
It does not change launcher data, shaderpack archives, system graphics providers
or firmware. A timeout/collection failure exits unsuccessfully; retaining a
structured failure record for those exceptions remains a tooling improvement.

## Remaining review debt and acceptance boundaries

- The native baseline has 26 diagnostics: four unchecked formatting/diagnostic
  results, two static-initialization warnings, eleven adjacent-parameter warnings,
  six narrowing conversions, an unchecked driver-index `atoi`, one existing
  fallback switch without a default, and one shared-pointer-by-value warning. That last
  copy is intentional: context release erases the map entry that can own its
  input, so changing it to a reference would create an ownership bug. Counts are
  a regression threshold, not a blanket justification for the other diagnostics.
- Existing native build warning suppression outside the audited files and 47
  Android lint warnings remain debt. The checks do not claim repository-wide
  lint cleanliness, exhaustive taint analysis or sanitizer coverage.
- Existing narrow unsigned/float image widening and the named `colorimg8`
  compatibility exception still need numerical-contract evidence. The new
  unsupported-format errors are intentional; do not advertise full image-format
  compatibility merely because a qualifier can be translated.
- The image-uniform setter correction does not complete the existing logical
  query, shared-unit alias or stale-remapping model. The 15-case error probe
  was expanded to 18 checks after exposing and correcting ordinary-uniform
  backend-error propagation. Its expected desktop errors remain strict. The
  logical-query and alias issues are separate from this setter correction.
- Live Mixin application, loader lifecycle, shader reload, world transitions,
  FSR quality/preset changes and rendering on the real launcher remain acceptance
  gates for each newly supported tuple. Minecraft 26.2 requires the actual OpenGL
  backend; a Vulkan renderer does not become supported by the presence of a JAR.
- A Mixin `RETURN` callback does not execute if the target final-pass method
  throws. The bridge now clears a leftover final-pass scope at the next frame
  boundary or pipeline destruction. That recovery still needs a live lifecycle
  check; normal return/finally restoration is not proof of this case.
- The bridge supplies camera/depth inputs to the existing upscaler. This work
  does not establish object motion, full reactive-mask fidelity, frame generation,
  anti-ghosting quality or a performance gain.
- Context ownership tests use a recording backend. GPU resource reclamation,
  shared-context behavior and repeated real context destruction still require
  target tests. The reviewer did not operate hardware; target results belong to
  the separate hash-bound execution report.
- X2 capability claims require a probe of the actual Android provider. Qualcomm's
  published GPU/API feature list does not establish its future ANGLE/GLES limits.

The next qualification should bind the loaded core marker and artifact hashes to
the actual launcher process, then exercise the supported NeoForge 21.1.262 lane
before qualifying the additional bridge profiles. Preserve original shaderpack
archives and keep failures observable.
